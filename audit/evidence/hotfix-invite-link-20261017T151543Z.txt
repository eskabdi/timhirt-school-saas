# Hotfix: invite email opened the login page, not "set password" (owner report 2026-10-17)
## Root cause
Production auth config mailer_templates_invite_content (custom HTML set in the dashboard) linked the
"Accept Invitation & Setup Password" button (MSO and normal variants) to {{ .SiteURL }} = https://www.edux.et (login)
and never used {{ .ConfirmationURL }}. It also printed {{ .Data }} (the raw metadata map) as the school name.
The app side was correct: supabase-js flowType implicit, detectSessionInUrl, /accept-invite sets the password.
## Fix (commit 8c30a21)
supabase/templates/invite.html (now versioned; config.toml [auth.email.template.invite]): both button hrefs and a
plain-text fallback use {{ .ConfirmationURL }}; school name from {{ .Data.school_name }} ("your school" if absent).
onboard-tenant and invite-tenant-admin send school_name in the invite metadata.
Validated by rendering with Go html/template: 3 verify hrefs, 0 hrefs to the site root, school name / fallback both render.
## Deploy (production)
